Navigation Guide

Use the screen tabs above or select a box inside the flow map. The main student journey is: Student Home → Daily Check-in → Save Entry → Monthly Summary. Selecting a low mood opens support choices. Staff members see class-level summaries, while teachers only see class-level anonymous trends after at least 10 responses. Seven consecutive very-low entries first trigger a private consent choice for the student, not an automatic referral.

GRADUATED CONSENT

Student-controlled support

1. Private prompt

After seven consecutive very-low entries, only the student sees a gentle invitation. No teacher or social worker is notified yet.

2. Student choice

The student chooses anonymous chat, a meditation tool, or “Not now.” Refusing does not create a referral.

3. Anonymous first contact

If the student agrees, the social worker receives a support request under a random alias. Diary text remains unavailable.

Blue Koala

Shared with social worker: “A student has voluntarily requested a five-minute anonymous text chat.”

Not shared: name, class, diary text, full mood history, or teacher dashboard data.

Exception for immediate danger

The prototype should clearly explain any school safeguarding exception before use. Emergency risk should follow the school's approved safeguarding procedure, not an undisclosed automated referral rule.

ROLE-BASED ACCESS CONTROL

Who can see what?

Student

  • Sees personal check-ins and 30-day average
  • Diary remains only on the student's device in this prototype
  • Controls whether to request anonymous support
  • Can preview the teacher view

Teacher

  • Sees anonymous class-level trends only
  • No names, individual records, diaries, aliases, or chats
  • Charts require at least 10 responses
  • Cannot export student-level wellbeing data

Social worker

  • Receives only student-authorised support signals
  • Starts with a random alias
  • Cannot read diary text
  • Identity is revealed only if the student chooses, subject to stated emergency safeguards

Administrator

  • Manages accounts and role permissions
  • Cannot decrypt or read diary text
  • Audit logs record access and configuration changes
  • No teacher-role override into personal data
Diary privacy

For this GitHub Pages prototype, diary text is stored only in browser Local Storage. A production design should use audited end-to-end encryption or local-only storage. Local Storage alone is not suitable on shared school devices because anyone using the same browser profile may access it.
